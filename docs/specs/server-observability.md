# 规格：服务器诊断、连接与日志

## 状态与目标

已确认（2026-10-21）。用户选择按只读首轮方案推进，网络配置安全回滚另行设计。

目标用户通过 SSH 使用没有图形桌面的 Linux。第一轮让用户在终端内检查 Mihomo、
定位 TUN 接管故障，并查看连接与日志。优先只读、证据清楚、资源有界，不自动修复网络。

## 假设与范围

- 保持原生单一 YAML、Mihomo 独立进程、本机托管与外部 Controller 两种模式。
- 保留现有 1–4 页和快捷键，新增 5 连接、6 日志、7 诊断；适配 80×24 SSH 终端。
- 新增不启动 TUI 的 `doctor` 子命令，便于 SSH 排查与脚本收集结果。
- 默认检查不向互联网发起探测；真实 HTTPS 探测必须由用户明确触发。
- 第一轮不新增 Cargo 依赖，不升级内核、不修改 CI，也不自动安装或替换系统二进制。
- 本轮不实现配置限时确认、持久回滚计时器、自动重启、WebDav、Profile 或 Merge/Script。
  网络配置安全恢复作为下一轮独立设计，不能用 Controller 健康检查代替 SSH 连通性验证。
- 本轮完成后提供代码、验证结果和使用说明；GitHub 推送及服务器二进制替换另行明确执行。

## 第一轮行为与验收条件

### A. 只读诊断

命令约定：

```bash
mihomo-tui doctor
mihomo-tui doctor --json
mihomo-tui doctor --probe
mihomo-tui --controller http://127.0.0.1:9093 doctor
```

密钥沿用 `MIHOMO_SECRET`，不把密钥放入探测 URL 或报告。诊断不得调用工作区初始化，
即使配置不存在也不能生成、导入或覆盖配置，更不能安装、启动或重启服务。

每项结果明确区分通过、警告、失败、未知和不适用，包含证据摘要与可操作建议：

1. 读取配置、连接 Controller、读取版本与运行时 TUN 配置分别报告。
2. 本机模式检查 `mihomo.service`、`/dev/net/tun`、TUN 网卡、IPv4 策略规则和路由表。
   尊重自定义设备名和路由表编号；不能确定时显示未知，不能硬编码为故障。
3. 只有相关 TUN 自动路由功能开启时才要求对应检查。手动路由、TUN 关闭的场景不误报。
4. 识别 `goto` 指向不存在优先级等已知故障；查表入口和路由存在只证明结构检查通过，
   不能表述为流量已接管。IPv6 没有覆盖的部分明确标出，不能概括为整机网络健康。
5. 检查命令缺失、权限不足、超时、无 systemd 或无法解析响应时报告未知及原因，
   不阻止其余项目完成。
6. 显式外部 Controller 模式只检查所连接的核心，不拿本机网卡、networkd 或 systemd
   状态当成远端状态；对应本机检查标记不适用。
7. 报告包含采集时间与适用范围。JSON 采用固定字段和可预测的状态值；已确认的失败
   返回非零退出码，无已知失败不等于所有项目都已验证健康。

`--probe` 第一版使用固定的 `https://github.com/`，发出一个有超时的普通 HTTPS 请求，
不读取代理环境变量、不显式指定本地 HTTP/SOCKS 代理、不跟随重定向、不传送 Controller
密钥，不下载完整响应体。先不提供任意 URL 探测，避免扩大特权网络请求边界。

探测时观察 Controller 中目标相关的新连接，分别报告 HTTP 结果、观测到的入口、
规则与链路。没有观测到连接、并发请求无法唯一归因或 API 不可用时必须显示未确认。
请求成功本身不能证明走了 TUN，更不能证明最终不是 DIRECT；一次采样也不是持续健康保证。

诊断页复用同一报告逻辑，进入或刷新只执行默认只读检查；真实探测使用单独提示的显式按键。
采集在后台执行，不阻塞终端操作，同类任务不并发堆积。

### B. 连接工作区

- 从鉴权的 `GET /connections` 读取真实活跃连接，本机和外部模式均可用。
- 显示目标主机或 IP、协议、入口类型、命中规则、代理链、上传和下载字节数。
- 支持搜索过滤和选中连接的详情。链路顺序按上游含义呈现，不能误把组名当成最终节点。
- 只在需要时定期刷新，支持手动刷新；尽量按连接 ID 保持选择稳定。
- 清楚区分尚未采集、正在加载、没有活跃连接、采集失败和保留的过期快照。
- 第一轮不提供关闭连接的写操作；不持久保存访问历史。
- 快照大小、展示条目数和后台消息数量有上限，超限明确提示，不无限占用内存。

### C. 日志工作区

- 使用鉴权的 `GET /logs?level=info` HTTP JSON 行流，无需增加 WebSocket 依赖。
- 默认读取 info 及以上实时日志，不改动核心日志级别；不暗示具有历史日志。
- 后台读取、缓冲有界，支持滚动、暂停展示及清空本地缓冲。
- 进入页面时建立订阅，离开或退出时停止；超时、断线与重连状态可见。
- 取消、重连后旧任务消息不得覆盖新状态；网络等待不能卡住键盘响应。
- 单行长度、缓冲行数和传输队列有上限；明确处理畸形 JSON 与超长行。
- HTTP 流当前采用 3 秒超时，重连可能漏日志；连续 3 次无数据/失败后暂停自动重连，
  需按 `r` 或重新进入页面，避免核心安静时无限创建订阅。完整历史仍由 journalctl 获取。
- 对日志中的 URL 凭据、查询参数、已知 API 密钥和控制字符做保护；API 报错同样脱敏。
  仅保存在内存，不新增日志文件或自动上传。显示脱敏不等于可随意公开完整报告。

## 技术栈与结构

Rust 2024；沿用 Ratatui 0.29、Crossterm 0.29、Reqwest 0.12 blocking、Serde/Serde JSON、Clap 4.5。

```text
src/main.rs                doctor 命令解析及非 TUI 分发
src/mihomo.rs              只读 Controller HTTP 调用及鉴权
src/models.rs              新增页面枚举，保留现有状态模型
src/app.rs                 页面导航与后台任务接入
src/diagnostics/           诊断采集、证据评估、报告与测试
src/observability/         连接/日志模型、有界缓冲、终端展示与测试
docs/server-guide.md       命令、页面和故障判断说明
docs/specs/                本规格与交付进度
```

模块细分以最少的实际边界为准，不引入通用事件总线或插件框架。不顺便重构已有订阅编辑流程。

## 代码风格与接口

沿用 `snake_case` 函数名、显式结果类型和中文面向用户的提示，例如现有接口：

```rust
pub fn version(&self) -> Result<CoreVersion, String> {
    // HTTP 鉴权与解析封装在 Controller 边界内。
    // 调用方只处理版本结果，不拼接 API 地址或传递秘密到展示层。
}
```

检查状态使用枚举而不是从提示文案反推真假；调用完成时间、错误及快照有效性分别保存。
外部数据在边界校验，输出到终端前处理控制字符。系统命令用固定程序和独立参数执行，
不用 shell 拼接，不把原始配置或整段命令输出直接作为诊断报告。

```bash

git diff --check
```

不在测试里重启真实 networkd/Mihomo，不删真实规则，不修改 `/etc`，不打印真实密钥。
最终真实验证只使用新构建文件，不默认替换已安装二进制。

## 边界

- 始终：后台 I/O、有界资源、明确超时、脱敏、失败可见、保留既有配置与用户修改。
- 先确认：新依赖、CI 修改、内核升级、安装到系统路径、网络配置写操作或 GitHub 推送。
- 禁止：诊断隐式启动/重启服务，自动改 networkd，向探测站点传送 Controller 凭据，
  将未知当成功，保存或提交真实访问历史/订阅秘密。
